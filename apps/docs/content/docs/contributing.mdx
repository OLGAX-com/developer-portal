## Workflow

1. Fork/branch, make your change.
2. Run the checks locally before opening a PR:

```bash
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
```

3. Open a pull request. CI runs the same checks.

## Conventions

- Strict TypeScript — avoid `any`; prefer `unknown`, interfaces, and generics.
- Business logic (XP, badges, missions, leaderboards, mentorship) lives in
  `packages/database/src/services` so it's reusable outside `apps/web` too.
- Never hardcode badges or missions in application code — they're rows in the `Badge` /
  `Mission` tables (see `packages/database/prisma/seed.ts`).
- Keep components focused (`ContributorCard`, `ProjectCard`, not one giant dashboard component).
- Comments should explain *why*, not *what* — the code should already say what it does.

## Adding a database change

```bash
# edit packages/database/prisma/schema.prisma, then:
pnpm --filter @olgax/database exec prisma migrate dev --name your_migration_name
```

## Adding a UI primitive

shadcn/ui components live in `apps/web/components/ui`. Add more with:

```bash
pnpm dlx shadcn@latest add <component> -c apps/web
```
